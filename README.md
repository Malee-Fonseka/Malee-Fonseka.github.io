# Malee-Fonseka.github.io

My personal portfolio: an introduction, in-depth project case studies, and my education, experience and skills.
It's plain HTML and CSS with no build step, hosted on GitHub Pages. The only JavaScript is the home page's background animation and the projects page's area filter, and every page still works without it.

**Live site:** https://malee-fonseka.github.io/

## Structure

```
index.html                 Home: introduction card over the animation, then Get in touch
projects.html              Project index: area filter, then one card per project
about.html                 Summary, then education, experience and skills
404.html                   Shown by GitHub Pages for missing URLs
assets/
  css/style.css            The only stylesheet; colours and fonts are tokens at the top
  js/hero-animation.js     Picks, loads and switches the home page animation
  js/anim-fish-tank.js     The two animations, each loaded only when shown
  js/anim-conway.js
  js/anim-murmuration.js   A third animation, off for now (never loaded)
  js/project-filter.js     The projects page's area filter
  img/                     Favicon, and a portrait placeholder (hidden for now)
projects/
  _template/               Starter for new case studies (not published)
    _case-study.md         Write the case study here; Claude generates index.html from it
    index.html             The markup generated pages follow
    images/
  screen-shield/           One folder per project
    index.html
    images/
```

## Adding a project

1. **Copy the template folder.** Copy `projects/_template/` to `projects/<slug>/`, where the slug is lowercase with hyphens, for example `projects/weather-station/`.
2. **Add your images** to `projects/<slug>/images/`: the screenshots, diagrams and photos the case study uses. SVG, PNG, JPG and WebP all work.
3. **Write the case study in Markdown.** Open `projects/<slug>/_case-study.md`. Fill in the front matter at the top (title, summary, tech stack, links and the card for the projects page), then write the body. The comment under the front matter explains the extra blocks: key numbers, callouts, flow diagrams, galleries and code listings.
4. **Generate the page.** Ask Claude to "generate `projects/<slug>/index.html` from `_case-study.md`". It writes the page, adds the card to the top of `projects.html`, and updates the `entries` count and `updated` month there. After changing the Markdown, ask again: the page is rewritten and the existing card is updated. Make your changes in the Markdown, not in `index.html`, or the next generation overwrites them.

The Markdown file's name starts with an underscore, so GitHub Pages never publishes it (see [Deploying](#deploying)) and Jekyll can't turn it into a page that clashes with `index.html`.

**To write the HTML by hand instead,** delete `_case-study.md` and replace everything marked `EDIT` in `projects/<slug>/index.html`. The comment at the top of that file lists every building block. Then copy the card template from the comment above the card list in `projects.html`, paste it at the top of the list, fill it in, and update the `entries` count.

Section numbers (`SEC 01`), figure numbers (`FIG. 01`), contents numbers and card numbers (`P-01`) are all generated by CSS, so you never need to renumber anything by hand.

### Building blocks for case studies

| Block | Markdown | HTML | Use it for |
| --- | --- | --- | --- |
| Section | `## Heading`, or `## Heading {#id}` to choose the id | `<section class="cs-sec" id="…"><h2>…</h2>` | A numbered section with an entry in the contents list |
| Key numbers | `::: metrics` with `- **42%** label` items | `<ul class="metrics">` | Two to four headline figures |
| Figure | `![alt](images/…)` with an `*italic caption*` on the next line | `<figure class="figure">` | Images, screenshots and exported diagrams, with an auto-numbered caption |
| Zoomable figure | Automatic for every image | `<a class="figure__media" href="…">` around the image | Lets readers open large diagrams full size |
| Padded figure | `{pad}` straight after the image | `figure--pad` | Diagrams that need space around them |
| Flow diagram | `::: flow` with `1. **Step** detail` items; `{key}` highlights one | `<ol class="flow">` with `<li class="flow__node">` | Step-by-step pipelines drawn in pure HTML; arrows are automatic |
| Gallery | `::: gallery` holding figures | `<div class="gallery">` holding figures | Several screenshots side by side |
| Callout | `::: note` or `::: decision`, with an optional `"label"` | `<aside class="callout">` or `callout--decision` | Notes and design decisions |
| Table | A Markdown table | `<div class="table-wrap"><table>` | Requirements, comparisons, results |
| Code | `` ```js title="path/file.js" `` | `<figure class="code">` | Code excerpts with a filename header |

### How a page is generated from Markdown

Claude follows the markup in `projects/_template/index.html`, so generated pages match hand-written ones:

- **Head:** the `<title>` is "*title* · Maleesha Fonseka", the meta description is "Case study: " followed by `description`, and the `og:` tags use the title and description. The breadcrumb ends with the slug.
- **Header and footer:** the same as in `projects.html`, so nav and contact links stay current.
- **Contents:** one entry per `##` section, in order.
- **Figures:** each image links to its full-size file, loads lazily, and gets a `width` and `height` read from the image file, so the page doesn't jump while it loads.
- **Code:** escaped, and coloured with the `tok-*` classes (keywords, strings, numbers, comments and function names).
- **Links:** external links open in a new tab, like every other external link on the site.
- **Card:** status `complete`, `in progress` or `archived` becomes `status--done`, `status--wip` or `status--archived`. The area becomes the card's `data-area` id (`ai`, `data-engineering`, `software-systems`, `research` or `other`) and its name in the card's footer. The card's tech stack falls back to the page's if it has none of its own.
- **Comments** in the Markdown are notes to yourself and are left out of the page.

For diagrams, draw them in [draw.io](https://app.diagrams.net/), [Excalidraw](https://excalidraw.com/) or Figma and export them as SVG or PNG. A dark background (`#0d1011`) with light lines matches the site best.

### The area filter

The panel above the cards filters them by area: AI, data engineering, software systems, research or other. Each card's `data-area` decides where it appears, and `assets/js/project-filter.js` counts the cards in each area, so adding a card is all it takes. The chosen area goes in the address (`projects.html?area=research`), so you can link straight to a filtered view. Without JavaScript the panel stays hidden and every card shows.

- **Area colours:** the `--area-*` tokens in section 1 of `style.css`, used for the square beside each area name.
- **Adding an area:** add a button to the panel in `projects.html` with a new `data-area` id, a colour token and a `[data-area="…"]` rule beside the others in `style.css`, then list it in the card template comment and in `_case-study.md`.
- **Card numbers** (`P-01`) count only the cards showing, so they restart from `P-01` in each filtered view.

## The home page

### Background animation

The fish tank plays behind the introduction card every time the page loads. The **switch** button at the top left moves on to Conway's Game of Life, then back to the fish tank, and the label beside it names the one that's playing. Nothing is stored in the browser.

- **Order and default:** the `ANIMATIONS` list at the top of `assets/js/hero-animation.js`. The first entry plays on load, and the switch steps through the rest in order.
- **The murmuration** is off for now. `anim-murmuration.js` is still in the repository, but it isn't in `ANIMATIONS`, so it's never downloaded. To bring it back, add its line after the fish tank; the comment above `ANIMATIONS` has it ready to copy.
- **Colours:** the custom properties on `.hero__anim` in `style.css`. The five `--life-*` colours are Conway's, and the murmuration uses them too; the `--tank-*` colours are the fish tank's water and dots. The fish colourways are in `FISH_STYLES` in `anim-fish-tank.js`.
- **The original animations** in `docs/animations/` no longer feed the site. Edit the `assets/js/anim-*.js` files instead.
- **Adding an animation:** write a file like the others that registers `window.heroAnimationRegistry[id] = mount`, where `mount(canvas, { visibleMargin })` draws into the canvas and returns a `destroy()` function. Then add a line to `ANIMATIONS`.

Each animation pauses while it's off-screen, including when Get in touch is in view. Visitors who prefer reduced motion get a still frame, and without JavaScript the hero shows its normal background.

### Fitting one screen

The home page snaps between two full-screen sections, the introduction and Get in touch. That only takes one scroll if the introduction is never taller than the screen; if it is, the browser lets you scroll *inside* it, and one scroll stops short. So its spacing and text sizes scale with the screen's height:

- **Wide but short screens** (laptops at 125–150% display scaling) put the name on one line.
- **Phones** use slightly smaller text and buttons.
- **Very short phones** (620px tall or less) hide the intro paragraph; the same introduction is on the about page.

If you add or lengthen anything in the introduction card, check that it still fits at about 1280×590 (a 1920×1080 laptop at 150% scaling) and on a phone. In the browser's developer tools, the introduction should be no taller than the window minus the 60px header.

## Previewing locally

Open `index.html` in a browser, or run a local server from the repository root:

```sh
python -m http.server 8000
```

Then visit http://localhost:8000. The VS Code **Live Server** extension also works. (`404.html` uses absolute paths, so it only renders correctly when served.)

## Deploying

The repository is named `Malee-Fonseka.github.io`, so GitHub Pages publishes it automatically:

1. Push to `main`.
2. On GitHub, go to **Settings → Pages** and set the source to **Deploy from a branch**, using `main` and `/ (root)`.
3. The site appears at https://malee-fonseka.github.io/ within a minute or two.

GitHub Pages runs its default Jekyll build, which skips folders that start with an underscore. That's why `projects/_template/` stays private. Don't add a `.nojekyll` file unless you also want the template to be published.

## Customising

- **Colours, fonts and spacing:** edit the tokens in section 1 of `assets/css/style.css`. Every page uses them.
- **Font:** Fira Code from Google Fonts, set at weight 450 to match Fira Code Retina.
- **Header and footer:** both reach the screen edges on every page, while page content stays in the centred column. They're repeated in every HTML file because there's no templating, so if you change a nav link (home, projects, about), update it in each page, including `projects/_template/index.html`.
- **Footer height:** the footer must stay exactly `--footer-h` (78px) tall, or the home page can't scroll fully onto Get in touch. If you change its padding or font size, update the token too.
- **Snapping:** only the home page snaps, through `<html class="snap">`. Every other page scrolls freely.
- **About page:** the portrait and the certifications section are hidden in HTML comments in `about.html`. Uncomment them to bring them back. The layout switches to two columns on its own when the portrait is present.
- **Text selection:** turned off on every page by `user-select: none` on `body` in `style.css`. Delete those two lines to allow selecting text again.
- **Contact details:** search the project for `your.email@example.com` and `your-handle` and replace them with your own.
