# Malee-Fonseka.github.io

My personal portfolio: an introduction, in-depth project case studies, and my education, experience and skills.
It's plain HTML and CSS with no build step and no JavaScript, hosted on GitHub Pages.

**Live site:** https://malee-fonseka.github.io/

## Structure

```
index.html                 Landing page: introduction and contact links
projects.html              Project index: one card per project
about.html                 Education, experience, skills, certifications
404.html                   Shown by GitHub Pages for missing URLs
assets/
  css/style.css            The only stylesheet; colours and fonts are tokens at the top
  img/                     Favicon and portrait
projects/
  _template/               Starter for new case studies (not published)
    index.html
    images/
  screen-shield/           One folder per project
    index.html
    images/
```

## Adding a project

1. **Copy the template folder.** Copy `projects/_template/` to `projects/<slug>/`, where the slug is lowercase with hyphens, for example `projects/weather-station/`.
2. **Add your images** to `projects/<slug>/images/`. A 16:9 cover (1200×675) is used both on the page and on the project card. SVG, PNG, JPG and WebP all work.
3. **Write the case study.** Open `projects/<slug>/index.html` and replace everything marked `EDIT`. The comment at the top of the file lists every building block. Delete the ones you don't need, and copy the ones you want more of.
4. **Add a card.** In `projects.html`, copy the card template from the comment above the card list and paste it at the top of the list. Point its link at `projects/<slug>/index.html` and its thumbnail at your cover image. Update the `entries` count in the page header.

Section numbers (`SEC 01`), figure numbers (`FIG. 01`), contents numbers and card numbers (`P-01`) are all generated by CSS, so you never need to renumber anything by hand.

### Building blocks for case studies

| Block | Markup | Use it for |
| --- | --- | --- |
| Section | `<section class="cs-sec" id="…"><h2>…</h2>` | A numbered section; add a matching link in the contents list |
| Key numbers | `<ul class="metrics">` | Two to four headline figures |
| Figure | `<figure class="figure framed">` | Images, screenshots and exported diagrams, with an auto-numbered caption |
| Zoomable figure | `<a class="figure__media" href="…">` around the image | Lets readers open large diagrams full size |
| Flow diagram | `<ol class="flow">` with `<li class="flow__node">` | Step-by-step pipelines drawn in pure HTML; arrows are automatic |
| Gallery | `<div class="gallery">` holding figures | Several screenshots side by side |
| Callout | `<aside class="callout">` or `callout--decision` | Notes and design decisions |
| Table | `<div class="table-wrap"><table>` | Requirements, comparisons, results |
| Code | `<figure class="code">` | Code excerpts with a filename header |

For diagrams, draw them in [draw.io](https://app.diagrams.net/), [Excalidraw](https://excalidraw.com/) or Figma and export them as SVG or PNG. A dark background (`#0d1011`) with light lines matches the site best.

## Previewing locally

Open `index.html` in a browser, or run a local server from the repository root:

```sh
python -m http.server 8000
```

Then visit http://localhost:8000. The VS Code **Live Server** extension also works. (`404.html` uses absolute paths, so it only renders correctly when served.)

## Deploying

The repository is named `Malee-Fonseka.github.io`, so GitHub Pages publishes it automatically:

1. Push to `main`.
2. On GitHub, go to **Settings → Pages** and set the source to **Deploy from a branch**, using `main` and `/ (root)`.
3. The site appears at https://malee-fonseka.github.io/ within a minute or two.

GitHub Pages runs its default Jekyll build, which skips folders that start with an underscore. That's why `projects/_template/` stays private. Don't add a `.nojekyll` file unless you also want the template to be published.

## Customising

- **Colours, fonts and spacing:** edit the tokens in section 1 of `assets/css/style.css`. Every page uses them.
- **Font:** Fira Code from Google Fonts, set at weight 450 to match Fira Code Retina.
- **Header and footer:** these are repeated in every HTML file, because there is no templating. If you change a nav link, update it in each page, including `projects/_template/index.html`.
- **Contact details:** search the project for `your.email@example.com` and `your-handle` and replace them with your own.
